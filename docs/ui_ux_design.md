# UI/UX Design: ページ構成・ナビゲーション・ユーザーフロー設計

---

## 1. サイトマップ

```
/                           ... トップページ
├── /apps/                  ... アプリ一覧
│   ├── /apps/stillmotion/  ... StillMotion 詳細ページ
│   └── /apps/dayrhythm/    ... DayRhythm 詳細ページ（Coming Soon）
├── /download/              ... ダウンロードページ（ローカルサーバー等）
│   └── /download/stillmotion-server/ ... StillMotion Server
├── /privacy/               ... プライバシーポリシー
├── /terms/                 ... 利用規約
└── /contact/               ... お問い合わせ
```

### URL設計方針
- Hugo の Section / Page Bundle を活用
- 多言語対応: `/ja/...` `/en/...` のプレフィックス方式（Hugo i18n）
- 将来のアプリ追加は `/apps/{app-slug}/` に追加するだけで対応可能

## 2. 各ページの構成要素

### 2.1 トップページ (`/`)

| セクション | 内容 | 備考 |
|-----------|------|------|
| Hero | キャッチコピー + 簡潔な一文紹介 | 背景はミニマルなグラデーションまたは単色 |
| Featured Apps | アプリカード一覧（アイコン + 名前 + 一行説明 + リンク） | 最大3件を横並び表示 |
| Footer | 共通フッター | 詳細は後述 |

- **ミニマル志向**: ヒーローは文字中心。画像は最小限。スクロール量は少なく、1〜2画面で完結。
- Hero直下に Featured Apps を置くことで、ユーザーが即座に目的のアプリへ到達可能。

### 2.2 アプリ一覧ページ (`/apps/`)

| セクション | 内容 |
|-----------|------|
| Page Header | 「Apps」タイトル |
| App Cards | 各アプリのカード（アイコン、名前、一行説明、対応プラットフォームバッジ、ステータス） |

- カードはグリッドレイアウト（2列、モバイルでは1列）
- 「Coming Soon」バッジで開発中アプリを区別

### 2.3 アプリ詳細ページ (`/apps/stillmotion/`)

| セクション | 内容 | 備考 |
|-----------|------|------|
| App Hero | アイコン（大） + アプリ名 + サブタイトル + プラットフォームバッジ | |
| CTA Primary | App Store ボタン群（iOS/iPadOS/macOS） | プラットフォーム別にバッジ表示 |
| Overview | アプリの概要説明（2〜3段落） | |
| Features | 主要機能のリスト（アイコン + 見出し + 短い説明）| 3〜6個、グリッド配置 |
| Screenshots | スクリーンショットギャラリー | デバイスごとにタブ切替またはカルーセル |
| Local Server | ローカルサーバーの説明 + ダウンロードリンク | StillMotion固有セクション |
| CTA Secondary | App Store ボタン再掲 | ページ末尾でもう一度誘導 |

### 2.4 アプリ詳細ページ - Coming Soon (`/apps/dayrhythm/`)

| セクション | 内容 |
|-----------|------|
| App Hero | アイコン + アプリ名 + 「Coming Soon」バッジ |
| Teaser | 簡単な紹介文 + 対応予定プラットフォーム |

- 公開時に詳細セクションを追加するだけで切り替え可能

### 2.5 ダウンロードページ (`/download/stillmotion-server/`)

| セクション | 内容 |
|-----------|------|
| Page Header | ソフトウェア名 + バージョン |
| System Requirements | 対応OS・動作要件 |
| Download Links | macOS インストーラ / Linux バイナリのダウンロードボタン |
| Installation Guide | 簡潔なインストール手順（折りたたみ可） |

### 2.6 プライバシーポリシー (`/privacy/`)

| セクション | 内容 |
|-----------|------|
| Content | 法的テキスト。アプリごとのセクション分け。 |

- シンプルな長文ページ。目次（TOC）あり。

### 2.7 利用規約 (`/terms/`)

- プライバシーポリシーと同様のレイアウト。

### 2.8 お問い合わせ (`/contact/`)

| セクション | 内容 |
|-----------|------|
| Contact Info | メールアドレスリンク or 外部フォームへのリンク |

- GitHub Pages は動的フォームを持てないため、`mailto:` リンクまたは外部サービス（Formspree, Google Forms等）を利用
- ミニマルに保つ: フォーム埋め込みよりメールリンクを推奨

## 3. ナビゲーション設計

### 3.1 グローバルナビゲーション（ヘッダー）

```
[Logo/サイト名]          [Apps]  [Contact]  [EN/JA]
```

- **項目を絞る**: Apps / Contact / 言語切替のみ
- Logo クリックでトップへ
- Privacy / Terms はフッターのみに配置（ヘッダーを汚さない）
- Download は各アプリ詳細ページからの導線に限定

### 3.2 モバイルメニュー

```
[Logo/サイト名]          [☰ ハンバーガー]

展開時:
┌─────────────┐
│ Apps         │
│ Contact      │
│ ──────────── │
│ Privacy      │
│ Terms        │
│ ──────────── │
│ EN / JA      │
└─────────────┘
```

- ハンバーガーメニューはアイコンのみ（テキストラベルなし）
- 展開時はオーバーレイ表示（背景を暗く）
- アニメーションは控えめ（150〜200ms fade/slide）

### 3.3 フッター

```
┌─────────────────────────────────────────────┐
│  [Logo/サイト名]                             │
│                                              │
│  Apps            Legal            Connect    │
│  StillMotion     Privacy Policy   Contact    │
│  DayRhythm       Terms of Use               │
│                                              │
│  © 2026 [Company Name]. All rights reserved. │
└─────────────────────────────────────────────┘
```

- 3カラム構成（モバイルでは縦積み）
- 必要最低限のリンクのみ

### 3.4 パンくずリスト

- アプリ詳細ページ・ダウンロードページのみ表示
- 例: `Home > Apps > StillMotion`
- トップページ・一覧ページでは非表示

## 4. レスポンシブ対応方針

### 4.1 基本方針: モバイルファースト

- CSS は `min-width` メディアクエリで段階的に拡張
- コンテンツの読みやすさを最優先

### 4.2 ブレークポイント

| 名前 | 幅 | 対象デバイス |
|------|-----|-------------|
| `sm` | 640px〜 | 大きめスマートフォン（横向き） |
| `md` | 768px〜 | タブレット |
| `lg` | 1024px〜 | デスクトップ |
| `xl` | 1280px〜 | 大画面デスクトップ |

### 4.3 レイアウト変化

| 要素 | Mobile (<768px) | Desktop (>=1024px) |
|------|-----------------|-------------------|
| ナビ | ハンバーガーメニュー | 横並びリンク |
| App Cards | 1列 | 2〜3列グリッド |
| Features Grid | 1列 | 2〜3列グリッド |
| Screenshots | 横スクロール | グリッドまたはタブ |
| フッター | 縦積み | 3カラム |
| コンテンツ幅 | 100% (padding: 16px) | max-width: 1120px, 中央寄せ |

## 5. CTA戦略

### 5.1 原則

- **1ページにつき主要CTAは1種類**（混乱を避ける）
- ボタンは目立つが、ミニマルデザインを壊さない配色
- App Store 公式バッジを使用（Apple ガイドライン準拠）

### 5.2 CTA配置マップ

| ページ | Primary CTA | 配置位置 |
|--------|-------------|---------|
| トップ | 「Apps を見る」 | Hero セクション内（任意） |
| アプリ一覧 | 各カードがリンク | カード全体がクリッカブル |
| アプリ詳細 | App Store バッジ | Hero 直下 + ページ末尾 |
| ダウンロード | ダウンロードボタン | メインコンテンツ中央 |

### 5.3 App Store バッジの扱い

- Apple 公式の「Download on the App Store」バッジ SVG を使用
- macOS 版は「Download on the Mac App Store」バッジ
- プラットフォームごとに横並び（モバイルでは縦積み）
- watchOS は iPhone アプリ経由のため、iOS バッジに注記を添える

### 5.4 ローカルサーバーのダウンロード

- アプリ詳細ページ内の専用セクションにリンクボタン
- ダウンロードページへの誘導は控えめに（メインの App Store CTA を邪魔しない）
- ボタンラベル例: 「Download for macOS」「Download for Linux」

## 6. アクセシビリティ方針

### 6.1 基本準拠

- **WCAG 2.1 Level AA** を目標
- セマンティック HTML を徹底（`<nav>`, `<main>`, `<article>`, `<section>`, `<footer>`）

### 6.2 具体的な対応

| 項目 | 方針 |
|------|------|
| コントラスト比 | テキスト: 4.5:1以上、大文字テキスト: 3:1以上 |
| キーボード操作 | 全インタラクティブ要素にフォーカス可能。Tab順序は論理的に |
| スクリーンリーダー | 画像に alt テキスト。アイコンボタンに aria-label。ランドマーク適切に配置 |
| モーション | `prefers-reduced-motion` メディアクエリでアニメーション無効化 |
| フォントサイズ | rem ベースで指定。ブラウザのフォントサイズ設定を尊重 |
| 言語属性 | `<html lang="ja">` / `<html lang="en">` を適切に設定 |
| リンク | 下線またはホバー時の視覚的変化で識別可能に |
| フォーム要素 | ラベルと入力を明示的に紐付け（`<label for="...">`) |

### 6.3 テスト

- Lighthouse Accessibility スコア 90+ を目標
- axe DevTools による自動テストを推奨

## 7. ユーザーフロー

### 7.1 メインフロー: App Store へのアプリ取得

```
トップページ → Featured Apps カード → アプリ詳細 → App Store バッジ → App Store
```

### 7.2 サブフロー: ローカルサーバーのダウンロード

```
トップページ → StillMotion カード → アプリ詳細 → Local Server セクション → ダウンロードページ → ダウンロードボタン
```

### 7.3 サブフロー: 問い合わせ

```
任意のページ → ヘッダー Contact → お問い合わせページ → メール送信
```

---

## 8. 設計上の注意事項

- **ミニマル第一**: 装飾・アニメーション・情報量は常に「必要最低限か？」を問う
- **将来の拡張性**: アプリが増えても `/apps/{slug}/` パターンで統一的に追加可能
- **パフォーマンス**: 画像は WebP/AVIF で提供。アイコンは SVG。フォントは最小限のウェイトのみ
- **Coming Soon の扱い**: DayRhythm は軽量なティーザーページのみ。情報がないのに詳細ページを作らない
